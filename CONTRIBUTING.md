# Contributing

Thanks for helping keep this roadmap useful. It is a curated list, so the bar is "would this
genuinely help someone working through this stage?" — not "is this related to trading?".

## The three rules for a resource link

1. **It works.** Open it in a browser and confirm the page you are linking actually exists and
   covers what you say it covers. A dead or redirected-to-homepage link is worse than no link.
2. **It is free to read.** No affiliate or referral links, ever — not even ones that only add a
   tracking parameter. Content that is partly or fully paid is allowed *only* when clearly labelled
   as such in the line you add (for example: "free summary, the full course is paid").
3. **It is honest.** No "make $X per month" pages, no profit promises, no signal-selling, no
   invented statistics. If a page makes performance claims, that is fine to link as a *documented
   example* only if you can say where its numbers come from.

## Honesty rules for anything you write

- Numbers must be measured and attributable: state the source, the period, the symbol and the
  costs, or leave the number out. Never estimate a number and present it as a fact.
- No popularity claims that cannot be verified from the page you are linking (no star counts used
  as an argument, no "trusted by", no user counts).
- Performance examples must state whether costs are included and must show the benchmark they are
  compared against. If a strategy lost money, say it lost money.
- Mark anything you have not tested as untested. Promising that something "works" is a claim.

## Keep the structure

- A new resource goes **inside an existing stage**, in the stage where someone would actually need
  it. It does not get its own section.
- Keep the line format: `- <url> — one sentence saying what it teaches and why it belongs.`
- Do not change the stage order, rename stages, or remove the "Done when" line. If you think a
  stage is missing, open an issue with the case for it first — the eight stages map to a build
  order, and adding a stage changes the path for everyone.
- Time estimates stay framed as typical, and stay rough. They are not promises.
- Keep the "not a bot you can run" framing true: if a change would make this repository look like a
  ready-to-run trading system, it does not belong here.

## How to submit

1. Open a pull request that changes only what you propose: one stage, one or a few links.
2. In the description: which stage, what the link is, why it belongs, and the result of opening it
   yourself. If you are replacing a link because it broke, say so.
3. Fixing a dead or moved link is the most valuable contribution of all — those PRs are welcome on
   their own, with no new content attached.

Maintainers re-check links when reviewing and periodically afterwards; a link that stops working
will be removed rather than guessed at.
